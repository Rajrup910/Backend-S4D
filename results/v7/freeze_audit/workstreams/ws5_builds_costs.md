## 5. R-series factor isolation (task 4)
V6 specs (`members.py`): PanDerm-B backbone LR 1.25e-4 (= 5e-4 x 32/128), head LR 1.25e-4, layer decay 0.65, WD 0.05, drop path 0.2, warmup 10/50 of fine-tune steps, batch 32 x 1, 13,410-step budget (30 ticks, head stage 3 ticks). DINOv2-B backbone LR 1e-5 flat (no layer decay), head LR 1e-4, WD 1e-4, drop path 0.1, head dropout 0.3, warmup 0, same budget.
* R3: `layer_decay 0.80` only. One declared factor, head LR unchanged, but every block's LR changes (block 11 8.1e-5 -> 1.0e-4; block 0 7.1e-7 -> 8.6e-6 via 0.8^12 x 1.25e-4). Clean as "decay shape".
* R3b: `backbone_lr 5e-4` AND `head_lr 5e-4`, decay 0.65. This is 4x on both backbone and head: one "base LR" factor but the head LR moves too (head LR is a second knob; V6 also scaled it linearly). Block 0 becomes 5e-4 x 0.65^12 = 2.8e-6 (4x). Not isolated from head LR; the doc should call it "base LR incl. head". Because R3 and R3b change different parameters, they do separate decay from base LR; a combined arm is not planned (fine).
* R2 (DINOv2-B): `layer_decay 0.75` AND `backbone_lr 4e-5` (V6 flat 1e-5, head 1e-4 unchanged). Two factors in one arm. Under timm's decay, top block runs at about 3e-5 and block 0 at about 4e-5 x 0.75^12 = 1.3e-6 (lower than V6's flat 1e-5), so the lower half gets LESS LR than V6 while the top gets more. A gain or loss cannot be attributed to either factor.
* "Official PanDerm recipe LR 5e-4 at batch 128, not rescaled in code": source is `members.py` comment and `docs/V6_RUNSHEET.md:472` ("Repo `finetune_train.sh`; the code does not rescale `--lr`"). No copy of the PanDerm script exists in this repository (only the .pth). UNVERIFIED here (no network). Plan 13.2 verified only that 0.65 is BEiT's ViT-B decay, not the LR claim.
* Per-block weight movement: implemented only as a post-hoc script (`scripts/lr_audit_weight_movement.py`) comparing final checkpoints with pretrained weights; no in-trainer logging, no per-epoch hook. "With weight movement per block" is producible after a run from its `_last`/`_swad` checkpoint; "read at its first epoch" (13.10 step 3) is not (only `--log-steps` loss).
* V6 baseline movement (file): PanDerm block00 0.17% ... block11 11.31%; DINOv2 blocks 3.9-4.8% (so DINOv2 had near-uniform movement, which weakens the "under-trained, still rising" premise of R2 and is worth stating).

* B3: in-repo surrogate = squared hinge (margin 0.6) between each positive's escalation logit and the top-k negatives (k = ceil(0.2 x n_neg) per BATCH), averaged, added to CE with weight 1. Docstring explicitly says equivalence to LibAUC SOPA-s is NOT claimed; no document claimed equivalence (plan 10.9 item 4 offers "install LibAUC" as the alternative). Caveat: it is computed per micro-batch of 16 at 384 px (accum 2), where expected negatives about 12 and positives a handful, so k = 3 and many micro-batches contribute zero; the "SOPA-s limit" language overstates the closeness.
* B5/T-CF image maths: `darkness.py` converts via a frozen chromophore basis (optical density, `ch.compute_maps`, `basis.concentrations`, `exp(-reconstruct)`, clamp [0,1]), scales lesion melanin ABOVE the local skin level by k (soft lesion mask x valid-pixel mask; invalid pixels keep original), k log-uniform [0.5, 2], p 0.5. The docstring calls it "what the dark-lesion read measured" (an index), not physical melanin: fine. Residual wording risks: plan 12.3 R1 row "a physical intervention might" and section 6.2 line 206 "True Causes ... prior suppression ... aliasing" (section 9.5 row 360 already retracts it as unmeasured, but 6.2 is not marked). T-CF is described as an image-level intervention in 12.2, appropriate.
